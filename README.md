# LanternTrace Explorer

Interactive application and open research benchmark for spotted-lanternfly frontier forecasting.

**[Read the technical paper](output/pdf/lanterntrace-frontier-forecasting.pdf)**

An Electron prototype inspired by the Blue Corridors species explorer, adapted to show a spotted lanternfly invasion-front workflow.

![LanternTrace Explorer showing the inferred invasion front, public GBIF occurrences, freight corridors, and the time slider](docs/screenshot.png)

## Run

```bash
npm install
npm run data:gbif   # fetches the GBIF occurrence layer (not committed)
npm run model:build # trains/ranks 20 diffusion variants and precomputes display frames
npm start
```

`npm run data:gbif` writes `generated/observations.js`, which is gitignored because it is a ~14 MB derived artifact. The app runs without it — the public-occurrence layer is simply empty until you generate it.

## What is included

- Map/globe view with a dark, presentation-oriented basemap.
- Repeat-report core, short-range reporting-gap interpolation, optional forecast range, real public-coordinate GBIF occurrence records, transport corridors, and surveillance-site layers.
- Time slider with play controls for the 2019–2025 front snapshots.
- Twenty reaction–diffusion ablations, temporal backtests, selectable 2019–2025 monthly backcasts, and Settings-only 2026–2030 forecasts.
- A physics-informed neural residual constrained to correct the modeled front rather than create unconstrained detections.
- Precomputed monthly contours for smooth playback without solving the PDE on the renderer thread.
- Search for a small built-in set of places and regions.
- Evidence, action-priority, and methods/model-card panels.
- JSON export of the active front snapshot and visible layers.

## Data provenance

The occurrence layer is generated from the GBIF occurrence index with `npm run data:gbif`; its records are real public data and retain source identifiers.

Observed-period envelopes are derived from public reports. Prospective geometry is generated by `scripts/build-diffusion-model.py` from a diffusion ensemble using WorldClim 2.1, GBIF spotted-lanternfly and tree-of-heaven records, terrain resistance, climate, transport proximity, and a learned residual. See [`docs/model-literature-review.md`](docs/model-literature-review.md) for the evidence map and limitations. **Neither the occurrence envelope nor the forecast is independently field validated.**

The blue dashed observed-period surface is short-range modeled continuity across likely reporting gaps, not observed presence. Candidate backtests also reduce pseudo-absence penalties where a coarse urban-node reporting-effort proxy is low.

Each top-five model also includes 84 evidence-assimilating monthly backcast frames. At every 2019–2025 step, true dated reports anchor the state and the selected reaction–diffusion candidate advances the surrounding field. Display contours are interpolated from a lightly smoothed scalar field; the underlying solver remains on its documented 0.2° grid.

## Status

Research prototype, not a released forecasting product. `npm run pack` produces a local macOS app; the current development build is signed locally but not notarized or distributed.

## Research benchmark

The retrospective first-report benchmark and 11-page technical paper live under `research/`. To verify the locked inputs, run the numerical safeguards, regenerate every result and all eight figures, compile the paper twice, and require byte-identical PDFs:

```bash
research/reproduce.sh
```

The deliverable PDF is written to `output/pdf/lanterntrace-frontier-forecasting.pdf`. Its benchmark includes a fixed transfer of the published Cook et al. (2021) SLF dispersal kernel alongside learned and reaction–diffusion models. A post-hoc frozen replay fits learned coefficients only through 2023, verifies that the same coefficients are reused, and evaluates 2024–2025 with annual state updates. The paper treats endpoint inflation and model non-dominance as the result; the replay improves temporal separation but is not presented as preregistered, independent-species, or prospective field validation.

Generated result tables and the release PDF are committed for inspection. The large source occurrence snapshot and covariate caches remain checksum-locked local inputs because their upstream licenses and APIs require separate redistribution decisions; see `research/input-lock.json` and `research/results/data_provenance.json`.
